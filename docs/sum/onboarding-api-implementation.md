# Onboarding API Implementation

## 📋 Tổng quan

Implement API `PATCH /api/users/me/level` để cập nhật trình độ tiếng Nhật của user trong màn Level Selection.

---

## 🏗️ Kiến trúc Clean Architecture

```
Presentation Layer (UI)
    ↓
Domain Layer (Business Logic)
    ↓
Data Layer (API/Database)
```

## 💡 Lý do thiết kế

### 1. **Tách Domain Layer (Repository Interface + Use Case)**

**Lý do:**
- **Testability**: Có thể mock repository để test use case mà không cần API thật
- **Flexibility**: Dễ thay đổi implementation (từ API sang local storage) mà không ảnh hưởng business logic
- **Dependency Inversion**: Domain layer không phụ thuộc vào Data layer

**Ví dụ:**
```dart
// Domain layer chỉ định nghĩa contract
abstract class OnboardingRepository {
  Future<void> updateUserLevel(String levelCode);
}

// Use case chỉ biết đến interface, không biết implementation
class UpdateUserLevel {
  final OnboardingRepository repository; // ← Interface, not implementation
  UpdateUserLevel(this.repository);
}
```

---

### 2. **Tách Data Layer (API + DataSource + Repository Implementation)**

**Lý do:**
- **Separation of Concerns**: 
  - `OnboardingApi`: Chỉ định nghĩa endpoint (Retrofit)
  - `OnboardingRemoteDataSource`: Xử lý error, convert exception
  - `OnboardingRepositoryImpl`: Implement interface từ domain layer
- **Error Handling**: Centralized error handling trong DataSource
- **Code Generation**: Retrofit tự động generate code cho HTTP calls

**Ví dụ:**
```dart
// API: Chỉ định nghĩa endpoint
@PATCH('/api/users/me/level')
Future<void> updateUserLevel(@Body() Map<String, String> body);

// DataSource: Xử lý error
try {
  await _api.updateUserLevel({'level_code': levelCode});
} on DioException catch (e) {
  throw HttpException.fromDioException(e); // ← Convert to app exception
}
```

---

### 3. **Riverpod Providers cho Dependency Injection**

**Lý do:**
- **Auto Disposal**: Provider tự động dispose khi không dùng
- **Lazy Initialization**: Chỉ khởi tạo khi cần
- **Dependency Graph**: Riverpod tự động quản lý dependencies
- **Testability**: Dễ override providers trong tests

**Ví dụ:**
```dart
// Provider tự động inject dependencies
final onboardingDataSourceProvider = Provider<OnboardingRemoteDataSource>((ref) {
  final apiClient = ref.watch(apiClientProvider); // ← Auto inject
  return OnboardingRemoteDataSource.fromDio(apiClient.dio);
});

// UI chỉ cần gọi provider
await ref.read(updateUserLevelProvider(levelCode).future);
```

---

### 4. **FutureProvider.family cho API calls**

**Lý do:**
- **Caching**: Riverpod tự động cache kết quả theo parameter
- **Loading State**: Tự động quản lý loading/error/data states
- **Reactive**: UI tự động rebuild khi state thay đổi
- **Family**: Cho phép truyền parameter (levelCode) vào provider

**Ví dụ:**
```dart
// Family provider nhận parameter
final updateUserLevelProvider = FutureProvider.family<void, String>((ref, levelCode) async {
  final useCase = ref.watch(updateUserLevelUseCaseProvider);
  await useCase(levelCode);
});

// UI gọi với parameter
await ref.read(updateUserLevelProvider('N3').future);
```

## ✅ Lợi ích của kiến trúc này

1. **Testable**: Mỗi layer có thể test độc lập
2. **Maintainable**: Dễ sửa đổi, mở rộng
3. **Scalable**: Dễ thêm features mới
4. **Reusable**: Use cases có thể dùng lại ở nhiều nơi
5. **Type-safe**: Compile-time checking với Retrofit + Freezed
6. **Error Handling**: Centralized error handling
7. **Dependency Injection**: Tự động với Riverpod

## 📝 Notes

- **Code Generation**: Chạy `dart run build_runner build --delete-conflicting-outputs` sau khi tạo/sửa Retrofit API
- **Error Handling**: Tất cả DioException được convert thành HttpException trong DataSource
- **Provider Scope**: Providers được define ở feature level, không global
- **Naming Convention**: 
  - Repository interface: `OnboardingRepository`
  - Repository implementation: `OnboardingRepositoryImpl`
  - Use case: `UpdateUserLevel` (verb + noun)
  - Provider: `updateUserLevelProvider` (camelCase)
